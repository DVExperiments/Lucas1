# The Lucas Money Game v0.8

A four-week Success Avenue Money game in which learners run a small real business or take on paid household jobs. They record earnings and costs, try financial ideas in their business and everyday life, and track their progress toward a savings goal.

## Play

- Choose **Play at home** to create one learner and begin immediately. Switch to **Parent / caregiver view** to tailor or assign missions, review work and record weekly check-ins. Both views share the local save, and Home lists home games alongside groups.
- Start from **Home**. Open the **Test group** to explore Alex and Jamie’s examples, or create a group to start with an empty roster. Each group and the test group save independently.
- Choose **Add learner** to set up a business, learning level, savings goal and either solo practice or mentored play. In **My progress**, badges and bonus game points reward money skills and savings milestones at 25%, 50%, 75% and 100%.
- From a learner view, select the game logo to return to Home.
- In **My virtual shop**, spend earned game points on fixtures and themes or pin an upgrade to save for. Game points and real-business savings use separate balances.
- Record real sales and expenses in **Money log**. Activity rewards are tracked separately from business profit.
- Each week pairs a real-business mission with a money quiz and an activity outside the learner’s business. Close a week in solo practice or with a mentor check-in to earn points and settle the four buckets.
- In **Facilitator view**, choose a learner to view all weeks, money entries, submitted work, feedback, badges and savings. Edit profile details and open-week entries, or correct the note on a closed mentored week.
- To tailor a module, use the Week picker in the learner record and choose **Customise module**. Current and upcoming weeks are editable. Closed weeks keep their recorded module and amounts. Submitted written work retains the prompt the learner answered.
- Game progress is stored in the browser. Anyone using the same browser profile can switch views and see its local roster. Use fictional profiles when demonstrating.

## Publish with GitHub Pages

1. Extract the ZIP. Upload its contents to the root of your repository on the `main` branch (or the branch you already publish from). Keep `index.html`, `assets/`, and `.nojekyll` at the same level as this README.
2. If Pages is already publishing from that branch and folder, commit the update there. For a new site, open **Settings → Pages**, choose **Deploy from a branch**, select `main` and `/(root)`, and save.
3. Open the published link shown under Pages. This project runs directly in the browser without a build step.

[GitHub Pages publishing guide](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

For a local check, run `python3 -m http.server 8000` from the extracted folder and open `http://localhost:8000`.

Saved games are stored per browser and site URL. An update published at the same address can read earlier saves. To use a save again, return to the same browser and site address.
